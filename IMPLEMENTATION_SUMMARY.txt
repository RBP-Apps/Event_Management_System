🎯 HOW IT WORKS
---------------

CREATING QR:
1. User clicks "CREATE YOUR QR" button on profile page
2. Form opens with 4 fields: Name, Phone, Email, Company
3. Click "GENERATE MY QR"
4. Backend: POST /create-qr
5. Apps Script: Saves to Google Sheet, generates QR_ID (qr_timestamp_random)
6. Returns QR URL: yoursite.com/profile?qr=qr_xyz
7. Shows QR code image
8. User can download PNG or copy link

SCANNING QR:
1. Anyone scans QR code or clicks link
2. Opens: yoursite.com/profile?qr=qr_xyz
3. Frontend detects ?qr= parameter
4. Calls: GET /get-qr-profile/qr_xyz
5. Apps Script looks up QR_ID in Google Sheet
6. Returns: Name, Phone, Email, Company
7. Profile page displays person's info
8. User can download PDF or save contact
9. NO FORM NEEDED - instant profile view!

📊 DATA STORAGE
---------------

Google Sheets "Personal QR Profiles" sheet:

Row 1 (Headers):
  A: Name | B: Phone | C: Email | D: Company | E: QR_ID | F: Created Date

Example Row 2:
  Raj Kumar | 9999999999 | raj@company.com | ABC Pvt Ltd | qr_1719432000_5234 | 25-06-2026

Data Flow:
1. Create QR → Save to Sheet → Return QR_ID
2. Scan QR → Lookup QR_ID in Sheet → Return profile data

💡 IMPORTANT NOTES
------------------

1. QR_ID Format: qr_<timestamp>_<random>
   Example: qr_1719432000_5234
   Guarantees uniqueness

2. No Scan History: QR scans are NOT logged
   - Privacy friendly
   - No tracking overhead
   - Just direct profile view

3. Separate from Events: Personal QRs are independent
   - Event QRs: ?id=EVT-001
   - Personal QRs: ?qr=qr_xyz
   - Different Google Sheets
   - Different endpoints

4. Same Profile Page: Both event and personal QRs use same UI
   - App.tsx detects URL parameter
   - Calls appropriate endpoint
   - Shows same profile layout

5. No Database Needed: All data in Google Sheets
   - Easy to manage
   - No backend database
   - No migrations needed
   - Accessible to everyone
